# Upstream GitHub & Git Bare-Metal Technical Specifications

This reference provides exact technical invariants for Git internals, GitHub Actions execution limits, GraphQL optimization, and cryptographic supply chain attestations.

---

## 1. Git Bare-Metal Internals & Object Storage

### Object Model
- All objects are stored in `.git/objects/` indexed by their SHA-1 / SHA-256 hash.
- Format: `[type] [size]\0[content]`, compressed via DEFLATE (zlib).
- 4 Fundamental Types:
  - `blob`: Raw byte content of files. Mode/name is NOT stored in the blob.
  - `tree`: Array of directory entries: `[mode] [name]\0[binary SHA]`.
  - `commit`: References a root tree, zero or more parent commit SHAs, author/committer timestamps, and commit message.
  - `tag`: Annotated tag pointing to an object with signer metadata.

### Packfiles & Delta Compression
- When repository size grows, `git gc` packs objects into `.pack` files with a companion `.idx` file.
- Uses sliding-window delta compression: stores changes between similar blobs/trees rather than full copies.
- Reverse deltas: The newest version is stored whole; older versions are reconstructed via deltas (optimizing for HEAD checkout speed).

### History Surgery
- **Purge Large Blobs:**
  ```bash
  git filter-repo --strip-blobs-bigger-than 10M
  ```
- **Purge Specific Leaked Secret File:**
  ```bash
  git filter-repo --invert-paths --paths-to-remove path/to/secret.env
  ```
- Always verify reflog and force-push with `--force-with-lease`.

## 2. GitHub Actions Runner Architecture & Invariants

### Hardware & Resource Allocation
- Standard hosted runners (Linux): 4 vCPU, 16 GB RAM, 14 GB SSD storage.
- Standard hosted runners (macOS): 3-4 vCPU (ARM64 Apple Silicon), 14 GB RAM.
- Maximum workflow run duration: 72 hours (35 minutes on public PRs before auto-cancel heuristics).
- Concurrency groups: Use `concurrency: group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true` to prevent resource waste on superseded commits.

### Security Invariants (Fail-Closed)
- **Pin Actions to Immutable Commit SHAs:**
  Never use mutable tags like `@v4` in high-security workflows. Always pin to full 40-character SHAs:
  ```yaml
  uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2
  ```
- **Minimum Token Permissions:**
  Always specify top-level permissions explicitly:
  ```yaml
  permissions:
    contents: read
  ```
- **OIDC Tokens (Zero Long-Lived Secrets):**
  Use short-lived JWTs exchanged with cloud identity providers via the GitHub OIDC provider (`https://token.actions.githubusercontent.com`).

## 3. GitHub GraphQL API v4 Optimization Heuristics

### Rate Limit Mechanics
- GraphQL API assigns a point cost to each query based on node count and depth:
  $$\text{Cost} = \sum (\text{nodes queried}) \times \text{connections}$$
- Standard limit: 5,000 points per hour per authenticated token.
- A single optimized query fetching up to 100 repositories costs exactly **1 point**, whereas REST API would require 100+ HTTP calls incurring rate limit exhaustion.

### Optimal GraphQL Pattern for Repository Audit
```graphql
query($login: String!, $cursor: String) {
  repositoryOwner(login: $login) {
    repositories(first: 100, after: $cursor, ownerAffiliations: OWNER, orderBy: {field: PUSHED_AT, direction: DESC}) {
      totalCount
      pageInfo {
        hasNextPage
        endCursor
      }
      nodes {
        name
        isPrivate
        isArchived
        isFork
        stargazerCount
        pushedAt
        licenseInfo { spdxId }
        repositoryTopics(first: 10) {
          nodes { topic { name } }
        }
        object(expression: "HEAD:.github/workflows") {
          ... on Tree {
            entries { name }
          }
        }
      }
    }
  }
}
```

## 4. Software Supply Chain & Cryptographic Attestations

### SLSA (Supply-chain Levels for Software Artifacts)
- **Level 1:** Documented build process + Provenance metadata.
- **Level 2:** Hosted build service + Signed provenance (GitHub Actions native).
- **Level 3:** Isolated hermetic build environment + Non-falsifiable provenance generated by the runner infrastructure, not the user script.

### Sigstore & Cosign
- Keyless signing: Cosign uses GitHub Actions OIDC token to issue an ephemeral certificate from the Fulcio Certificate Authority and logs the signature into the Rekor transparency ledger.
- Verification command:
  ```bash
  cosign verify --certificate-identity https://github.com/owner/repo/.github/workflows/release.yml@refs/heads/main \
                --certificate-oidc-issuer https://token.actions.githubusercontent.com \
                ghcr.io/owner/repo:v1.0.0
  ```
